# AXIL-CLIENT requirements

Every requirement this specification owns, with the proof that closes it. Delivery state
and public evidence for each ID are recorded in [`status.json`](status.json); this file
defines what each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md),
the test contract in [`test-spec.md`](test-spec.md), and the work order in
[`tasks.md`](tasks.md).

| `AXIL-CLIENT-R001.1` | **One backend-adapter import seam.** Every desktop panel and the main cockpit window route all Arbora access through the shared gateway client facade and the single `BackendAdapter` seam; no module imports `meristem`, and agent workflows run on arbora rather than in-process. Caller chain: `axil()` (axil/axil.py:707) builds `Axil` (axil/axil.py:187), which creates the shared `GatewayClient` (axil/axil.py:194); every panel and `BackendAdapter` (axil/services/backend_adapter.py:22) reach Arbora only through that client. Shape: Source scan in tests/test_backend_adapter_seam.py walks `axil/` for imports of the harness package; reuse `BackendAdapter` (axil/services/backend_adapter.py:22) and `GatewayClient`, add no second adapter. | A source-tree scan test asserts no module under `axil/` imports `meristem`. | `AXIL-CLIENT-R001` | **Served backend-adapter seam (rollup).** Preserve the original client seam in R001.1 and the bounded dashboard transport and lifecycle in R001.2 and R001.3. | Each child meets its own acceptance; dashboard tests do not prove all panel or release behavior. |
